## B. Executive Summary and Root Causes

### 1. Three Observed Selection-Deletion Defects

When a user selects multiple lines or paragraphs in Scribe Native and deletes them at baseline `dfe1d135`, three visually jarring defects occur depending on document position:

1. **Near-Bottom / Tail Deletions ("shrink upward, then scroll back down"):** On the first rendered frame after deletion, the surviving content *below* the deleted region snaps instantaneously upward to meet the upper selection endpoint, leaving a blank void below the bottom of the document (or transient overscroll past `maxCanvasScroll`). On a subsequent message-loop turn, `UnifiedCanvasLayout.handleDeletionSettlement()` detects `currentScroll > maxCanvasScroll` (or `TAIL_ANCHOR` / `RESET_TO_TOP`) and animates the entire canvas *downward*, pulling upper and lower content down together as a disconnected second motion.
2. **Mid-Document Deletions ("lower content yanked upward and left there"):** On Frame 1, lower surviving content snaps instantaneously upward to meet the upper endpoint. Because `ScribeCodeEditor.beforeModification()` captures `preEditCaretScreenY` using `cur.leftLine, cur.leftColumn` (the **upper** selection endpoint), `ScribeScrollDeletionPolicy` resolves `targetTotalScroll == currentScroll` for `CARET_ANCHOR` — leaving lower surviving content permanently pulled upward rather than keeping the lower region anchored while gliding the upper region downward to close the void.
3. **Offscreen-Selection Deletions (Scenario E):** When the user selects text, scrolls away from the selection, and deletes, `MainEditorScreen` skips `ensureCursorVisibleAboveKeyboard` on `ACTION_DELETE`, `UnifiedCanvasLayout` suppresses cursor-visibility scrolling while `hasPendingDeletionSettlement` is true, and `CARET_ANCHOR` preserves the offscreen `preEditCaretScreenY`, failing to smoothly bring the collapsed caret into view.

### 2. Core Mechanism: Synchronous `WordwrapLayout.afterDelete()` Mutation

- **Root Cause in One Sentence:** Sora Editor's `WordwrapLayout.afterDelete()` mutates `rowTable` **synchronously on the UI thread** during `Content.deleteInternal()`, immediately collapsing the vertical document coordinate gap before the next `onDraw()`, while `UnifiedCanvasLayout` pins physical scroll at `preEditScrollY` and later applies only a uniform whole-canvas scroll translation.
- **Contrast with `breakAllLines()`:** Whereas `WordwrapLayout.breakAllLines()` (`WordwrapLayout.java:91-127`, Sora `0.24.6` audit) can run asynchronously, `WordwrapLayout.afterDelete()` (`WordwrapLayout.java:240-260`) runs synchronously on the UI thread: it deletes affected rows from `rowTable`, shifts subsequent `RowRegion.line` indices, and re-breaks `startLine` immediately inside `Content.deleteInternal()`.
- Because whole-canvas scroll (`scrollD + editor.offsetY`) moves upper and lower document regions uniformly, a physical scroll alone cannot hold lower surviving text visually stationary while gliding upper text downward, keep upper stationary while closing lower text upward, or converge both around the viewport center.

### 2. Baseline Selection-Deletion Event Sequence (`Confirmed` at `dfe1d135`)

1. **`beforeModification` (`ScribeCodeEditor.kt:719-771`):** `ScribeDeletionSnapshotCoordinator` records `PreModificationSnapshot` using `cur.leftLine, cur.leftColumn`; `CodeEditor` calls `cursorAnimator.markStartPos()`.
2. **`Content.deleteInternal` -> `afterDelete` (`Content.java:510-553`, `ScribeCodeEditor.kt:773-816`):** `afterDelete` promotes the snapshot to `UnifiedCanvasLayout.beginPreEditDeletionSnapshot(..., markPendingSettlement = true)`, then `WordwrapLayout.afterDelete()` synchronously collapses `rowTable`.
3. **Synchronous `ContentChangeEvent(ACTION_DELETE)` (`ScribeCodeEditor.kt:354-387`, `MainEditorScreen.kt:1670-1683`):** `MainEditorScreen` skips `ensureCursorVisibleAboveKeyboard`; `ScribeCodeEditor` notifies deletion start and posts `canvas.handleDeletionSettlement(smooth = true)`.
4. **Frame 1 Render (`UnifiedCanvasLayout.kt:1506`):** `hasPendingDeletionSettlement = true` pins `scrollD + editor.offsetY` at `preEditScrollY`, so Frame 1 renders the synchronously shrunken `rowTable` uncompensated.
5. **Posted `handleDeletionSettlement()` (`UnifiedCanvasLayout.kt:730-837`):** Classifies `RESET_TO_TOP` / `TAIL_ANCHOR` / `CARET_ANCHOR` and starts whole-canvas `ScribeCanvasGlideAnimator` (causing delayed scrollback near bottom, or zero motion mid-document).

### 3. Summary of Rejected Alternatives & Sora Version Findings

- **Why Sora `0.24.6` Is Retained (`Confirmed`):** Diffing Sora `0.24.6` (`87055c45`) against `0.24.7` (`ab9f2cb2`) shows `0.24.7` adds semantic/diagnostic/inlay providers and `lastPreparedLine = -1`, but provides zero split-region translation or layout-freeze hooks. V1 retains `0.24.6` unchanged; optional `0.24.7` upgrade is deferred to [Phase 6](./phase-6.md).
- **Why Alternative Rendering Approaches Were Rejected:**
  - *Dual `super.onDraw()` with `clipRect()`:* Wipes Pass 1 during Pass 2's `WHOLE_BACKGROUND` fill (`EditorRenderer.java:465`), culls shifted lower rows via unexpanded `firstVis`/`lastVis`, and double-executes cursors, scrollbars, and edge effects.
  - *Offscreen `Bitmap` / `Picture` snapshots:* Cannot obtain pixels for offscreen surviving boundaries (Scenario D), captures stale cursor/selection state, and adds large bitmap memory churn per deletion.
  - *Phantom `rowTable` gap rows in `WordwrapLayout`:* Breaks Sora `Content` ↔ `Layout` offset mapping, IME `CursorAnchorInfo`, touch hit-testing, and accessibility indices.
  - *Selected Basis:* Keeping `Content` and `WordwrapLayout` 100% authoritative immediately while splitting rendering inside a custom `ScribeEditorRenderer : EditorRenderer` under a dedicated `ScribeGapCollapseController`.

## F. Important Source Facts That Still Require Verification

### 1. Source-Level Facts Already Established in the Investigation

- **Scribe Repository Facts (`Confirmed` against `dfe1d135`):**
  - `gradle/libs.versions.toml:44` pins `soraEditor = "0.24.6"` and `app/build.gradle.kts:14-19` sets `minSdk = 23`, `compileSdk = 37`, `targetSdk = 37`.
  - `MainEditorScreen.kt:1465, 1624, 1681, 2057` renders `UnifiedCanvasLayout` with `docBottomPadding`, `isLineNumberEnabled = false`, and an `ACTION_DELETE` guard skipping `ensureCursorVisibleAboveKeyboard()`.
  - `ScribeCodeEditor.kt` performs `beforeModification` (`719`), `afterDelete` (`773`), `handleDeletionSettlement` (`847`, `1453`, `1463`), `applyFormattedTextSilently` (`1022`), `isWordwrapReady()` (`1205`), `updateImageDescription` (`2081`), `removeImageTag` (`2095`), and `ensureCursorVisibleAboveKeyboard` calls.
  - `UnifiedCanvasLayout.kt` maintains integer `maxCanvasScroll`, directly assigns `scrollCoordinator.totalScroll = currentScroll` (`858`), and hosts `handleDeletionSettlement()` (`730`).
  - `ScribeScrollAnimation.kt` contains baseline `scrollCoordinator.finishAnimation(opId)` calls at lines `107` and `167`, and `cancel()` (`185-202`) invokes `activeGlideOnEnd` and `onCancelledCallback`.
  - `ScribeScrollDeletionPolicy.kt` (`498-512`) returns `AfterInsertAction.None` on overscrolled non-empty `Content.replace()`.
- **Sora `0.24.6` Audit Facts (`Confirmed` in baseline Sora source audit; external to `Scribe-Native` repo):**
  - `WordwrapLayout.afterDelete()` (`WordwrapLayout.java:240-260`) runs synchronously on the UI thread during `Content.deleteInternal()` (`Content.java:510-553`).
  - `Content.replace()` (`Content.java:585-587`) invokes `deleteInternal()` before `insertInternal()`.
  - `EditorRenderer.drawView()` (`EditorRenderer.java:461-698`) drives the 10-layer render pipeline once per frame, bypasses `RenderNodeHolder` when `isWordwrap == true` (`1421-1445`), and skips `postDrawCursor` `DrawCursorTask`s when `cursorAnimator.isRunning()` (`592-598`).
- **Claims Intentionally Downgraded or Corrected From Original Report:**
  - `RC-8` runtime frame timing (`~8–16 ms` Frame-1 gap, `~250–350 ms` glide duration) remains **`Likely` / `Unverified`**, not a confirmed measurement. *(Note: `ScribeScrollAnimation.kt` ticks via `postOnAnimationAction(glideFrameRunnable)`, not `ValueAnimator`.)*
  - `HandleStyleDrop` (`48-68` cited in the original report) is a Sora class, not inside `ScribeCodeEditor.kt`.

1. **Read the relevant phase document first:** Start from [`index.md`](./index.md) and read the target `phase-N.md` extract before inspecting or modifying code.
2. **Use this companion document for context only:** Use Sections B–F to understand *why* the defect happens and which baseline methods/files are involved.
3. **Follow `implementation_plan.md` for all implementation decisions:** Every state transition, formula, safety bound, eligibility rule, API name, and test assertion comes exclusively from [`implementation_plan.md`](./implementation_plan.md).
